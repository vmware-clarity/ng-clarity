2Class diagram: model and validators

+ public, # protected, − private. Groups only accept the two node classes. A filter keeps its field definition by reference and reads its validator once, in the constructor.

3Component tree

What <clr-advanced-filters> renders. ClrAdvancedFilters is the only public component. Groups render themselves recursively. Filters are shown as text; adding and editing happen in a popover. The module exports only ClrAdvancedFilters.

4A change, step by step

The user edits a filter of a nested group and clicks Apply, keeping the same field. Everything is synchronous: every subscriber has the change before set() returns, and clrFilterChange comes last.

Step 5: if the validator returns a code, set() throws a ClrAdvancedFilterValidationException and nothing changes. The editor only applies conditions the validator accepted (section 8). Step 6: if the operator and the value are the same as before, set() returns without emitting.

5Every mutating call

Each call checks first and throws having changed nothing, or changes the tree and then emits. A change is { node }: the node whose own state changed. It is emitted on that node and on each of its ancestors, the root last. The ancestors are the ones the node had when the call was made.

new ClrAdvancedFilter(field, operator, value?) a field definition is given (Error); the field's validator, or the base one, accepts operator and value (ClrAdvancedFilterValidationException). A value for IS_EMPTY throws. a new node, its own root; validator read once; an array value is copied and frozen — always
new ClrAdvancedFilterGroup() — a new empty AND group, its own root — always
group.addChild(node, index?) node is a group or a filter; not this group or one of its ancestors inserted at index (its position after the call; a missing, non-integer or out-of-range index means at the end); moved if it had a parent; keeps id and subtree added or reordered: group. Moved out of another group: two changes, the old parent first, then group, each up to its own root the node already is at that position
node.remove() — detached with its subtree; stays usable and can be added again the former parent the node has no parent (a root)
group.clear() — all children detached; logic back to AND; same id ("Clear all") group already an empty AND group
group.logic = value value is a ClrAdvancedFilterLogic member (Error) the logic group same logic

filter.value = v the validator accepts the current operator with v (exception with the code) the value; arrays are copied and frozen filter same value (arrays compared item by item, with Object.is)

A node without a parent is the root of its own tree: a new node, a removed one, or the root of a filter. A removed or cleared subtree keeps working: its changes reach its own root. Subjects are created on the first read of changes and never complete.

6Changes made by subscribers

Listener A of the root reacts to change #1 by switching the root's logic (change #2). The queue makes sure listener B still gets #1 before #2. Without it, B would see #2 first. AdvancedFilterChangeQueue is a singleton (static readonly instance, private constructor): one queue for every node of every tree, so a change of one tree made while another tree's change is being delivered waits too. It is empty again before the outermost mutating call returns.

7Add and edit, through the popover

The condition lives in the editor until Apply. The tree changes only on Apply. A filter's field never changes, so picking another field for an existing filter replaces it with a new filter at the same position.

The editor gets its field from the component's fields, which carry the built-in validators. For an existing filter it looks the field up by key and falls back to the filter's own definition. The filter row writes its text with AdvancedFilterText, for example "Budget: greater than 60".

8Validation

ClrAdvancedFilterValidator.validate(condition) checks the field key, then the operator, then the value, and returns the first problem or null. The base class checks the shape only. Each subclass sets fieldType and adds the rules of its type. A condition that is valid for a type is also valid for the base class.

ClrAdvancedFilters, for each entry of clrFields A field with its own validator is kept as it is. A type without a built-in validator is kept as it is.

9Values per field type

The shape of the value depends on the operator: none for IS_EMPTY (undefined), [from, to] for BETWEEN (both inclusive), a non-empty array for IN, one value otherwise. The editor (AdvancedFilterValueEditor) is chosen by the field type and the operator.

NUMBER a finite number; BETWEEN: [from, to] with from ≤ to NUMBER: clrNumberInput; NUMBER_RANGE: two clrNumberInput (From, To) formatNumber() with LOCALE_ID
BOOLEAN true or false, with EQUALS BOOLEAN: two clrRadio (True, False) "True" / "False" (advancedFilterTrue, advancedFilterFalse)
DATE an ISO date without a time of day, of a day that exists: "2026-10-20". It names a day, the same in every time zone. A range is written with "{FROM} and {TO}". A missing value, as the operator setter can leave, is written as "(missing value)".

Date inputs

  • The date inputs' ngModel is text in the locale's display format. ClrAdvancedFiltersValue provides its own LocaleHelperService and DateIOService, which the datepicker entry point now exports.
  • ISO date to text: AdvancedFilterIsoDate.toDate() (local midnight), then dateIO.toLocaleDisplayFormatString().
  • Text to ISO date, for typing and calendar picks alike: dateIO.getDateValueFromDateString(), then AdvancedFilterIsoDate.fromDate(). Text that is not a date yet gives no value.
  • When the emitted value comes back through [value], the text stays as typed.
  • A range editor keeps both bounds and emits [from, to] on every change. A missing bound is undefined, so the value is REQUIRED until both are set. An empty input (null or '') gives undefined.

12Invariants

What the code guarantees at all times.

Model

  • A node has at most one parent, and is listed exactly once in that parent's children.
  • parent and children always agree: only the group writes parent links, while it changes its own list.
  • No cycles: a group can't be added to itself or to one of its descendants.
  • Groups only hold ClrAdvancedFilterGroup and ClrAdvancedFilter nodes.
  • One logic per group: AND and OR never mix on one level.
  • A new filter is complete. The value setter and set() keep it complete. Only the operator setter can make it incomplete; error then says why.
  • A filter's field never changes, and its validator is read once.
  • children and array values are frozen; children is replaced exactly when the list changes.
  • Ids are generated once and never change.
  • A failing call throws before anything changed, and emits nothing. A call that changes nothing emits nothing.
  • A change is emitted on the changed node, then on each ancestor, the root last; the same frozen object each time.
  • Changes are delivered in the order they were made, through one queue for the page, before the outermost call returns.

Component

  • The UI never adds an incomplete filter: Apply works only when the field's validator returns null.
  • The component changes the given root instance. Anything that is not a ClrAdvancedFilterGroup starts a new empty AND root.
  • clrFilterChange emits the root after each change the user makes, never for changes made in code.
  • The consumer's field definitions are never changed: built-in validators go on copies.
  • Filters whose field key is no longer in clrFields are removed, once clrFields was given.
  • The view shows filters before groups; the model keeps its own order.
  • Users can't add groups beyond clrMaxDepth (default 3, the root included). Deeper trees built in code are shown as they are.
  • A filter keeps its field definition by reference, but toJSON() writes only the field key.

13The pills layout

[clrLayout]="'pills'" shows the same root and fields as pills; the tree stays the default. The root is always AND and is not shown. Every child of the root is one pill.

How Apply writes the edit

Popover Field type Write
Add filter DATE, NUMBER, STRING A new group with the logic and one filter per row, added as the root's last child. Always a group, even with one row.
Add filter ENUM, BOOLEAN One filter (one row), added as the root's last child.
Edit, group pill any In place: the logic is set, the rows' filters are edited with set(), filters without a row are removed, new rows are added, and the children follow the rows' order. Ids are kept.
Edit, filter pill, one row any filter.set().
Edit, filter pill, more rows DATE, NUMBER, STRING A new group takes the filter's place. The filter moves into it and keeps its id, or is removed when its row was removed. Then the group is written as above.

Rows

  • A popover always has at least one row. A new field starts with one row: the field's first operator, no value.
  • One logic per pill, set with the switch next to the field. Between two rows, a disabled button shows it. A line separates the field and its switch from the rows, once a field is picked.
  • ADD, after the last row, adds a row. The switch and ADD are offered for DATE, NUMBER and STRING only. The operator select is hidden for single-operator types.
  • × removes a row. On the last row it clears the operator and the value, and is disabled while they are cleared.
  • Apply is enabled only when the field's validator accepts every row. Escape and clicking outside discard the edit.
