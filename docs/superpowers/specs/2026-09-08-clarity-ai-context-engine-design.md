# Design: ARIA-first context engine, shipped as `@clr/angular/ai`

Date: 2026-09-08
Status: approved for planning
Supersedes the packaging and DOM-extraction design of the `@clr/ai` POC on `dtsanevmw/ai-assist-poc`.
Companion analysis: [`docs/CONTEXTUAL_ENGINE_GAP_ANALYSIS.md`](../../CONTEXTUAL_ENGINE_GAP_ANALYSIS.md)

## Context

The POC ships a contextual engine that gives AI agents a structured snapshot of the page — route,
rendered components and their state, available actions, application annotations. It works, and its
core ideas (pull-only snapshots, budgets, values off by default, a live tracker, a cross-frame
protocol) are sound.

Two problems motivate this redesign.

**Clarity knowledge lives in the wrong place.** `dom-context-collector.ts` hardcodes eight
Clarity-specific extractors keyed on Clarity selectors and CSS classes (`clr-modal`,
`.modal-dialog`, `clr-dg-row.datagrid-selected`, `.alert-danger`, `form[clrForm]`). Every new
Clarity component means editing `@clr/ai`; every Clarity markup change silently breaks it; and the
whole table describes exactly one UI library. An application using `@clr/ui` (CSS-only Clarity),
another component library, or plain semantic HTML gets almost nothing — even though `@clr/ui` is a
first-party Clarity distribution.

**The package split is not the story we want to tell.** `@clr/ai` is a separate artifact with its
own install, release and version-compatibility story. Shipping the capability inside `@clr/angular`
means it arrives with a Clarity minor version — no new dependency for consumers to adopt, and a
single release note.

The key observation behind the redesign: **an accessibility tree is already a semantic description
of what is on screen and what state it is in.** Clarity Angular maintains it for other reasons —
`aria-expanded` (54 usages), `aria-current` (33), `aria-selected` (16), `aria-sort`, `aria-modal`,
and roles `grid`/`columnheader`/`row`/`gridcell`, `dialog`, `tablist`/`tabpanel`, `combobox`,
`option`, `treeitem`, `switch`, `status`. The current collector already leans on this in places
(it reads `aria-sort`, `aria-selected`, `aria-expanded` rather than Clarity classes). Reading the
accessibility tree instead of Clarity selectors describes Clarity Angular, `@clr/ui`, other
libraries and plain HTML with one implementation.

## Goals

1. Zero Clarity-specific selectors or class names in the context engine.
2. Equivalent context from Clarity Angular markup, `@clr/ui` CSS-only markup, and plain semantic
   HTML.
3. Ship as `@clr/angular/ai`, available with a Clarity minor release.
4. Components supply only what ARIA genuinely cannot express.
5. Where ARIA is missing because of an accessibility defect, fix the defect rather than work around
   it.

## Non-goals

- The AI Assist UI band (panel, field signpost, diff review surface) and the transport/protocol
  band. Both remain on `dtsanevmw/ai-assist` and are tracked in the gap analysis. The
  `@clr/angular/ai` entry point is named to accommodate them later.
- Backwards compatibility of the snapshot shape. `@clr/ai` is unreleased; there are no consumers.
- General accessibility remediation beyond the four defects this work depends on.

## Decisions

| Decision       | Choice                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------- |
| Coverage       | ARIA-first; Clarity Angular, `@clr/ui` CSS-only and plain HTML all first-class              |
| ARIA gaps      | Fixed in `@clr/angular` as accessibility defects, not published around                      |
| Inclusion rule | Has an ARIA role (explicit or implicit), **or** an accessible name, **or** a hyphenated tag |
| Packaging      | `@clr/angular/ai` secondary entry point; the `@clr/ai` package is dropped                   |

## Architecture

### Packaging

`projects/ai/` moves to `projects/angular/ai/`, keeping `contextual/` as a plain subfolder with no
nested `ng-package.json`, so a future `ai/chat/` sits beside it without moving files.

| Change  | Detail                                                                                |
| ------- | ------------------------------------------------------------------------------------- |
| New     | `projects/angular/ai/ng-package.json`, `projects/angular/ai/index.ts`                 |
| New     | `projects/angular/ai/ai.api.md`, generated by the existing `scripts/api-extractor.js` |
| Deleted | `projects/ai/` tree, `projects/ai/package.json`, `clr-ai.api.md`, `contextual.api.md` |
| Deleted | the `clr-ai` project in `angular.json` (its `build` and `test` targets)               |
| Deleted | the `@clr/ai` and `@clr/ai/*` entries in `tsconfig.json`                              |
| Updated | `projects/demo`, `projects/website`, `docs/CONTEXTUAL_ENGINE.md` imports              |

`tsconfig.json` already maps `"@clr/angular/*": ["projects/angular/*"]`, so `@clr/angular/ai`
resolves with no new path configuration.

`@angular/router` is imported by the route-context code. This introduces no new dependency:
`@clr/angular` already imports `@angular/router` in `layout/nav/aria-current-link.ts`,
`layout/breadcrumbs/breadcrumbs.module.ts` and `button/button-group/button.ts`, and already does
not declare it as a peer dependency. Declaring it as an optional peer dependency is a correct
follow-up but is out of scope here.

### Where the publish contract lives

Components cannot import from `projects/angular/ai/`. Doing so would make
`@clr/angular/forms/combobox` depend on `@clr/angular/ai`, pulling the DOM collector, the
`MutationObserver` tracker and the router import into every application that renders a combobox.

The contract therefore separates from the engine:

| Location                                    | Contents                                                                                               | Depends on                                            |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| `projects/angular/utils/context/`           | `CLR_ELEMENT_CONTEXT_PROPERTY`, the callback type, `publishElementContext(host, callback): () => void` | nothing                                               |
| `projects/angular/ai/`                      | engine, collector, tracker, frame bridge, `clrContext` directive                                       | `@clr/angular/utils`                                  |
| `clr-combobox`, `clr-datagrid`, `clr-alert` | call `publishElementContext`                                                                           | `@clr/angular/utils` (already, e.g. `combobox.ts:48`) |

`publishElementContext` returns a teardown function and owns assign-on-init / delete-on-destroy, so
no component repeats the manual `delete` currently in `ClrCombobox.ngOnDestroy` (`combobox.ts:308`).

### The collector

One recursive descent replaces the current two-pass scan (extractor loop, then
`querySelectorAll('*')` with an `includes` + `contains` cross-check). Each element resolves to one
of four outcomes:

| Outcome                | When                                                                                                                      | Effect                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| **Skip subtree**       | `[data-clr-context-ignore]`, `aria-hidden="true"`, `hidden`, `!checkVisibility()`, `<script>`/`<style>`/`<template>`      | element and descendants ignored          |
| **Skip self, descend** | `role="presentation"` / `role="none"`, or fails the inclusion rule                                                        | not reported; children still evaluated   |
| **Include, descend**   | passes inclusion, and is neither a leaf role nor a summarized role (including role-less elements included by name or tag) | reported; children become its `children` |
| **Include, terminate** | passes inclusion, and its role is a leaf role or has a summarizer                                                         | reported; walk does not descend          |

Leaf roles — reported without descending, because their name comes from their contents:
`button`, `link`, `checkbox`, `radio`, `switch`, `textbox`, `searchbox`, `heading`, `img`,
`progressbar`, `slider`, `spinbutton`, `separator`, `option`, `tab`. (`alert` and `status` also
terminate, but via their summarizer below rather than as bare leaves.)

Ancestry comes from the walk itself, so today's `handledElements.includes(element)` and
`capturedElements.some(captured => captured.contains(element))` checks disappear. Complexity goes
from O(N × C × depth) to O(N). This is the fix for finding **C2** in the gap analysis.

**Inclusion rule.** An element is included when any of these holds:

1. It has an ARIA role — explicit via `role`, or implicit from its tag.
2. It has an accessible name.
3. Its tag name contains `-` (a custom element from any library).

`registerDomExtractor` remains the escape hatch for role-less, name-less markup such as a bare
`<div class="card">`.

**Implicit roles.** One ~30-entry HTML-AAM mapping — spec-defined, not Clarity-defined:

```
table→table  thead/tbody→rowgroup  tr→row  th→columnheader  td→cell
form→form  fieldset→group  legend→(name source)  output→status  progress→progressbar
nav→navigation  main→main  header→banner  footer→contentinfo  aside→complementary
section[named]→region  article→article  dialog→dialog  details→group  summary→button
h1..h6→heading  ul/ol→list  li→listitem  dl→list  a[href]→link  button→button
select→combobox|listbox  textarea→textbox  img[alt]→img  hr→separator
input→textbox|checkbox|radio|slider|spinbutton|searchbox|button (by type)
```

**Associating a custom element with its role — `element` resolution.** Clarity puts roles on inner
template elements, not on host elements. `<clr-datagrid>` carries no role; `role="grid"` sits three
levels down on `<div role="grid" class="datagrid-table">` (`datagrid.html:13`). `<clr-modal>`
likewise carries no role; `role="dialog"` is on an inner div (`modal.html:20`). A naive walk would
therefore report two nodes per component — an un-annotated custom element and, nested inside it, the
role-bearing div — and the promised `{ type: 'dialog', element: 'clr-side-panel' }` would never
occur.

Resolved by associating upward rather than hoisting downward. When an element is included, its
`element` field resolves as:

1. its own tag, when that tag is hyphenated; otherwise
2. the tag of the nearest hyphenated-tag ancestor that has no role of its own and is not separated
   from it by another included element; otherwise
3. absent.

A single upward walk, O(depth). `<div role="grid">` inside `<clr-datagrid>` resolves to
`{ type: 'grid', element: 'clr-datagrid' }`. `<div role="row">` inside `<clr-dg-row>` resolves to
`{ type: 'row' }` with no `element`, because `clr-dg-row` carries `role="rowgroup"` on its own host
(`datagrid-row.ts:56`) and so is reported in its own right.

Inclusion arm 3 (hyphenated tag) consequently fires only for custom elements that contain no
role-bearing descendant at all — genuinely un-annotated widgets, which is the case it exists to
catch.

**`type` resolution.** `type` is the ARIA role when the element has one; otherwise its tag name when
hyphenated; otherwise `'group'`. Every included element therefore always has a `type`.

**Accessible name.** A pragmatic subset of accname, in order: `aria-labelledby` → `aria-label` →
native label source (`<label for>`, wrapping `<label>`, `<legend>`, `<caption>`, `<figcaption>`,
`alt`, `title`) → text content, but **only for roles whose name comes from contents** (`button`,
`link`, `heading`, `tab`, `option`, `cell`, `columnheader`, `gridcell`, `row`, `rowheader`,
`checkbox`, `radio`, `switch`, `menuitem*`, `treeitem`, `tooltip`). Container roles never take
their name from subtree text, which is what prevents a region from absorbing the whole page as its
label. All names are truncated to `maxTextLength`.

**State.** One declarative attribute map, applied uniformly to every included element:

| Source                                                                                             | Reported as                                  |
| -------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `aria-expanded`                                                                                    | `expanded`                                   |
| `aria-selected`                                                                                    | `selected`                                   |
| `aria-checked`                                                                                     | `checked` (`true`/`false`/`'mixed'`)         |
| `aria-current`                                                                                     | `current`                                    |
| `aria-disabled`, `:disabled`                                                                       | `disabled`                                   |
| `aria-invalid`                                                                                     | `invalid`                                    |
| `aria-required`, `:required`                                                                       | `required`                                   |
| `aria-sort`                                                                                        | `sort`                                       |
| `aria-modal`                                                                                       | `modal`                                      |
| `aria-level`                                                                                       | `level`                                      |
| `aria-pressed`, `aria-readonly`, `aria-multiselectable`, `aria-haspopup`, `aria-busy`, `aria-live` | same name, camelCased                        |
| `aria-valuenow` / `aria-valuemin` / `aria-valuemax`                                                | `value` / `min` / `max`                      |
| native `open` (`<details>`, `<dialog>`)                                                            | `open`                                       |
| native `min`, `max`, `step`, `pattern`, `maxlength`                                                | same names                                   |
| native `value`, `checked`                                                                          | `value` — **only** under `includeFormValues` |

The native constraint attributes close the numeric-bounds and format-constraint gap identified in
the gap analysis (§2.3), and do so for every input on the page rather than only Clarity ones.

**Role summarizers.** Roughly eight, keyed on role. Each aggregates its subtree and terminates the
walk, which is what keeps a 10,000-row grid from producing 10,000 nodes:

| Role                        | Summary                                                                                                                                                                                                   |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `grid`, `table`, `treegrid` | `columns` from `columnheader` names, `rowCount` (`aria-rowcount` or counted `role="row"` elements), `selectedRows` (count of `[aria-selected="true"]` descendants), `sort` from the sorted `columnheader` |
| `tablist`                   | `tabs` (names), `activeTab` (the `[aria-selected="true"]` one)                                                                                                                                            |
| `list`                      | `itemCount`, first `maxItemsPerCollection` item names                                                                                                                                                     |
| `listbox`, `menu`           | option/item names, selected ones                                                                                                                                                                          |
| `radiogroup`                | `options`, `value` (under `includeFormValues`)                                                                                                                                                            |
| `form`                      | field children, each with name, label, type, `required`/`disabled`/`invalid`, constraints, and value under `includeFormValues`                                                                            |
| `dialog`, `alertdialog`     | name, `modal`, footer actions                                                                                                                                                                             |
| `alert`, `status`           | text, plus severity when the component publishes it                                                                                                                                                       |

The `form` summarizer replaces the `form[clrForm]` extractor and now works on any `<form>`,
resolving finding **C5**.

`collectClrDomActions`' separate `querySelectorAll('button.btn, a.btn')` pass is removed;
`role="button"` and `role="link"` nodes are already produced by the walk. `ClrPageContext.actions`
becomes the flattened list of `button` and `link` nodes that are **not** descendants of a node
reporting its own `actions` (a dialog or a summarized region), preserving today's behaviour of not
double-reporting modal and wizard footer buttons.

**Budgets.** `maxComponents` counts included nodes across the whole tree and stops the walk when
reached. `maxItemsPerCollection` caps summarizer arrays and `children` arrays.
`maxTextLength` caps every string. Defaults unchanged.

### Type vocabulary — breaking change

`ClrComponentContext.type` becomes the ARIA role (`'grid'`, `'dialog'`, `'tablist'`, `'alert'`,
`'form'`, `'region'`, `'navigation'`) instead of a Clarity name (`'datagrid'`, `'modal'`,
`'side-panel'`).

A new optional field carries what roles are too coarse to express:

```ts
export interface ClrComponentContext {
  /** ARIA role describing what this piece of UI is. */
  type: string;
  /** Tag name, when it adds information a role cannot — e.g. 'clr-side-panel'. */
  element?: string;
  label?: string;
  state?: Record<string, unknown>;
  actions?: ClrContextAction[];
  children?: ClrComponentContext[];
}
```

So a side panel is `{ type: 'dialog', element: 'clr-side-panel' }` and a modal is
`{ type: 'dialog', element: 'clr-modal' }` — the distinction survives without the engine knowing
what either component is. `element` is reported generically for any element; there is no table and
no branching on its value.

### Accessibility fixes in `@clr/angular`

Each is independently correct and worth doing on its own merits.

| #   | Component               | Change                                                                                                                                                                                                                                               | Today                                                                                                  |
| --- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1   | `clr-dg-row`            | `[attr.aria-selected]` on the **inner `role="row"` element** (`datagrid-row.html:8`), not the host — the host is `role="rowgroup"` (`datagrid-row.ts:56`) and `aria-selected` on a rowgroup is invalid ARIA. Plus `aria-multiselectable` on the grid | `[class.datagrid-selected]` only (`datagrid-row.ts:55`) — selection is imperceptible to assistive tech |
| 2   | form control containers | `[attr.aria-invalid]` when invalid and touched; `[attr.aria-required]` when required                                                                                                                                                                 | `aria-invalid` is set on the combobox only (`combobox.html:140`)                                       |
| 3   | `ClrCombobox`           | replace `'[class.aria-required]': 'true'` with `[attr.aria-required]` bound to actual requiredness                                                                                                                                                   | stamps a meaningless CSS class on every combobox; no CSS rule backs it (`combobox.ts:74`)              |
| 4   | `clr-alert`             | `role="alert"` for danger/warning, `role="status"` for success/info/neutral                                                                                                                                                                          | no role, no `aria-live` — the alert is never announced                                                 |

All four are attribute-only, so no visual regression is expected. The removed `aria-required` class
has no CSS rule anywhere in `projects/angular/styles` or `projects/ui/src` (verified). Accessibility
unit tests will need updating.

### What components still publish

Seven, via `publishElementContext`. The full audit of every component family, including the ones with
no gap, is in [`docs/CONTEXTUAL_ENGINE_COMPONENT_AUDIT.md`](../../CONTEXTUAL_ENGINE_COMPONENT_AUDIT.md).

| Component           | Publishes                                                    | Why nothing else can carry it                                                                                                                                           |
| ------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `clr-combobox`      | options while the popover is closed; current selection       | the options are not rendered while closed                                                                                                                               |
| `clr-datagrid`      | total row count; filtered columns; hidden columns            | the DOM holds one page; filter state is a CSS class with its value inside a closed popover; a hidden column is not rendered at all                                      |
| `clr-alert`         | exact severity                                               | `role="alert"` vs `role="status"` distinguishes only important from informational                                                                                       |
| `clr-wizard`        | per-step completion, error and navigability; count and index | completion and error are CSS classes, and the stepnav icon that labels them sits inside a button, which is described as a leaf; navigability has no ARIA representation |
| `clr-tree-node`     | whether a collapsed node has children; whether it is loading | `aria-expanded="false"` cannot say whether anything is underneath, a lazy subtree is absent from the DOM, and the loading indicator is a bare span with no `aria-busy`  |
| `clr-stepper-panel` | panel status                                                 | otherwise announced only as a transient live-region message beside the step, and only when complete or in error                                                         |
| `clr-timeline-step` | step outcome                                                 | the icon's label carries it, but a timeline is a list and its steps are list items, so the list is summarised by item name and the icon is never reached                |

One candidate resolved the other way: `clr-side-panel`'s pinned state was conveyed only by swapping
the pin icon's shape, but that **is** expressible in ARIA, so it became `aria-pressed` on the pin
button rather than a publisher — which also makes it perceivable to a screen reader.

## Testing

The load-bearing test is cross-surface equivalence: **three fixtures — Clarity Angular markup,
equivalent `@clr/ui` CSS-only markup, and plain semantic HTML — asserted to produce equivalent
context.** If that passes, the design's central claim holds.

Alongside it:

- unit tests per role for the state map and each summarizer
- contract tests for the three publishers, asserting the published shape against the real callback type
- accessibility unit tests for the four ARIA fixes
- a performance test on a 5,000-row grid page asserting a scrape completes within budget, guarding
  the O(N) claim and the tracker's viability

## Sequence

Each step is independently reviewable; only step 3 is large.

1. Publish contract into `projects/angular/utils/context/` — no behavior change
2. Move `projects/ai/` → `projects/angular/ai/`, wire the entry point, delete the `clr-ai` project — no behavior change
3. Generic ARIA collector replaces the eight Clarity extractors
4. The four `@clr/angular` accessibility fixes
5. The three publishers onto `publishElementContext`
6. Cross-surface equivalence tests and the performance test
7. Docs, demo page, website page

## Risks

| Risk                                                                                                                      | Mitigation                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Coverage becomes a function of how well each application annotates ARIA — `@clr/ui` markup is authored by the application | `registerDomExtractor` escape hatch; the inclusion rule's accessible-name and custom-element arms catch much of what a missing role would lose; document the ARIA expectations for `@clr/ui` |
| `type` as an ARIA role reads less evocatively in an agent prompt than `'datagrid'`                                        | `element` carries the specific identity alongside; revisit if prompt quality measurably suffers                                                                                              |
| Step 4 changes shipped components                                                                                         | separate commits, accessibility review, VRT run; all changes are attribute-only                                                                                                              |
| A role-driven walk may include more low-value nodes than the `clr-` prefix filter did                                     | summarizers terminate the walk on collection roles; `maxComponents` bounds the total; tune the leaf-role set against real application pages                                                  |

## Deferred

Tracked, not in scope here:

- **C1** — `enableGlobalAccess()` forwards caller options unsanitized, so
  `window.clrContext({ includeFormValues: true })` bypasses the application's decision not to
  expose values. Should reuse the frame bridge's `sanitizeOptions` against a host-supplied baseline.
- **C3** — form values change without DOM mutations, so a `context$` subscriber holds stale values
  once `includeFormValues` is on. Needs `input`/`change` listeners on the tracked root, or explicit
  documentation that value tracking requires `refresh()`.
- **C4** — `applyFormValues()` writes an agent's answer straight to the user's form with no review
  gate. Needs a preview mode before the diff review surface is ported.
- Declaring `@angular/router` as an optional peer dependency of `@clr/angular`.
- Possible simplification: the `clrContext` directive could publish through
  `publishElementContext` instead of `ClrContextRegistryService`, which would place annotations in
  the component tree at their real position and could retire the registry — provided no consumer
  needs element-less `ClrContextProvider` registration.
