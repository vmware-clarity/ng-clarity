Plugins in frames, described as one page

Each tab below is an iframe loading a plain static page, the way a plugin-based shell composes its UI, with the sandbox a shell grants its plugins (allow-same-origin allow-scripts allow-forms …). Note that for a plugin from the shell's own origin this sandbox isolates nothing: with both allow-same-origin and allow-scripts the framed page can lift its own sandbox, so it is exactly as trusted as the shell. A plugin served from this application's own origin appears in the snapshot as a frame node with its own controls, text and form as children — type into the inventory form and watch the value change on the right. The third plugin is served from a different origin ({{ thirdPartyOrigin || 'local demo only' }}), so the browser lets no script on this page read it — the sandbox makes no difference to that: allow-same-origin only lets a frame keep its real origin, it never grants the host access to another origin. The engine reports that a frame is there and nothing else, and such a plugin can instead ask this page for context through the frame bridge. Plugins served from the shell's own origin behave like the first two tabs.
