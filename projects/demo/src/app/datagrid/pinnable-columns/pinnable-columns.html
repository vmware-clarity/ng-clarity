Datagrid: Pinnable columns

A column with clrDgPinned is rendered to the left of the scrollable columns and stays visible while the rest of the datagrid is scrolled horizontally. Pinned columns keep their declaration order and are placed after the built-in row controls.

clrDgPinnable adds a pin toggle to the column header, so the user can pin and unpin the column from inside the datagrid instead of the application driving it.

Pin from the column header

Every column here is clrDgPinnable and none starts pinned. Scroll the datagrid sideways and use the pin icon in front of a column title. The columns are also sortable, so this is where to check that clicking the pin does not sort the column.

Keeping the pinned state in sync

The columns below combine clrDgPinnable with a two-way [(clrDgPinned)] binding. Ticking a checkbox pins the column and clicking a pin icon ticks the matching checkbox, which is what clrDgPinnedChange is for. The last column has no clrDgPinnable, so it can only be pinned from here.

With row controls

Selection, row actions and the expand caret keep their place at the very left. The pinned columns follow them, and the separator after the last pinned column marks the boundary with the scrollable ones. Toggling from the header here also checks that the pin does not select the row or open the action overflow.

With the detail pane

The detail pane shows a single, full width column, so there is nothing left to scroll. Pinning is suspended for as long as the pane is open and restored when it closes - the clrDgPinned input itself is not touched. The pin toggle stays in the header while the pane is open, so it is worth checking what it does there.
