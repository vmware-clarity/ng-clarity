Most applications need only a few of these: ClrContextService to read the page, configure({ application }) to name the application, and data-clr-context-redact for fields that hold secrets. Everything else is for finer control.

Services

ClrContextService

Reads the page and returns it as a snapshot. It can also keep the snapshot up to date as the page changes. Nothing is cached: every snapshot reads the page as it is.

Member Returns Effect
configure(config) void Sets how the application wants its context read (see Configuration below). Call it once, at startup. A second call replaces the whole configuration, and a snapshot taken before it uses the defaults.
snapshot(options?) Promise<ClrPageContext> Describes the page as it is now. options apply over the configured scope (see Snapshot options below). It first waits for providers that answer with a promise, up to timeoutMs each.
watch(options?) Observable<ClrPageContext> A snapshot now, and a new one each time the page, a value, an annotation or the route changes. Use it for a chat panel that always needs the current page. The page is watched while anyone subscribes. All subscribers share one watcher, so options apply to all of them. A provider that answers with a promise is first reported as 'clr-loading'.
changes(options?) Observable<ClrContextChange> What changed with each watch() snapshot (nodes added, removed and changed), so a conversation can send the difference instead of the whole page. The first lists everything as added.
enableGlobalAccess(propertyName?, options?) void Adds window.clrContext(), for browser agents and extensions. Any script can call it, so the caller is untrusted (see Untrusted callers below). options (ClrContextGlobalAccessOptions) take shareFormValues, shareFullUrl and snapshot options that cap what callers may ask for. An assistant built into the application does not need it.
disableGlobalAccess() void Removes window.clrContext().

Configuration

ClrContextConfig, passed to configure(). Every key is optional.

Key Default Effect
scope 'full' What every snapshot reads: a preset name or snapshot options (see Snapshot options below).
routes false Lists the router's routes in availableRoutes, so an agent can suggest a page that is not linked from the current one.
extractors [] Describe markup the engine cannot understand on its own, such as an element from another library with no role and no name. Each is a ClrContextDomExtractor: a selector and an extract(element, options) function. Its answer replaces the element and everything inside it.
timeoutMs 2000 How long a snapshot waits for each provider that answers with a promise. A provider that fails or is too slow appears as a region of type 'clr-unavailable'.
debounceMs 300 For watch(): how long the page must be quiet before it is read again.
maxWaitMs 2000 For watch(): the longest a change waits to be read while the page keeps changing.
application the host name Names the application and its views, as a ClrContextApplicationOptions. See the table below.
views 'all' 'all' reads every view. 'enabled' reads only views that have metadata, and reports the rest as enabled: false with nothing about the page.

application

Option Type Description
id String A stable id for the application, such as 'inventory'.
version String The application's version.
viewId () => string | null | undefined A function that returns the current view's id, called on every snapshot. Often not needed: put data: { viewId: 'vm-list' } on each route instead.
metadata () => object | null | undefined A function that returns a small object about the current view, called on every snapshot.

ClrContextRegistryService

Adds context that no element shows, such as a workflow model held in a service. Register a ClrContextProvider, an object with a getClrContext() method, and the engine calls it on every snapshot. The answer appears in the snapshot's regions. Context about an element goes on the element with [clrContext] instead.

Member Returns Effect
register(provider) () => void Adds a provider and returns a function that removes it. getClrContext() returns a ClrPublishedContext, or null when there is nothing to say. It may also return a promise, which snapshot() waits for.
unregister(provider) void Removes a provider, typically in ngOnDestroy.
notifyChanged() void Says that a provider's answer changed. watch() then reads the page again, even when the DOM did not change.

ClrMutationEngineService

Lets an agent fill in form fields and navigate. It never submits or clicks. It does nothing until the application provides a ClrMutationPolicy. Its results include the values on the page, so keep them inside the application.

Member Returns Effect
apply(operations, snapshotOptions?) Promise<ClrMutationReport> Runs the operations in order and returns a report: what each one did or why it was refused, a new snapshot, and what changed. Show the refusals in the chat panel from this report. A refused operation does not stop the rest.
plan(operations, snapshotOptions?) ClrMutationPlanEntry[] Says what apply() would do, without doing it. Pass the same snapshotOptions as to apply().

Operations

Each is a ClrMutationOperation, with operation set to its name.

Operation Fields Effect
setValue ref, description, value Gives a field a value: text, a number, true or false, an option's label, a date, or the rows to select. ref comes from the snapshot, and description must repeat the field's label, which guards against writing to the wrong field.
clear ref, description Empties a field.
navigate path, params?, queryParams? Goes to a route of the application through the router, with route guards applied. path is the pattern as availableRoutes lists it, such as clusters/:id.

Results

Property Type Description
applied Boolean Whether the operation took effect.
value, previous unknown The field's value now and before, so the application can undo it.
status, errors String, Object The form control's validity and validation errors after the write.
outcome, url String For a navigation: navigated, redirected, unchanged, rejected, superseded or failed, and the URL the page is now at.
refused, detail String Why the operation was refused (a ClrMutationRefusal), and a sentence saying what to do about it. The most common are unclassified (no policy), forbidden (the policy said no), declined (the user said no), redacted (a password or secret field), unbound (the field has no Angular form binding) and mismatch (the description does not match the label).

ClrMutationPolicy

Provided with provideClrMutationPolicy(policy) in the application's providers, not in a lazy route. It decides which writes are allowed and which need the user to confirm. Each method gets a ClrMutationTarget: the operation, the field's label, type and element, or the route, and the value about to be written.

Member Returns Effect
classify(target) 'reversible' | 'consequential' | 'forbidden' Required. Says what a write would do: reversible runs at once, consequential asks confirm first, and forbidden is refused. Decide by the element or the form control, not the label, which is translated and can repeat.
confirm(target) boolean | Promise<boolean> Optional. Asks the user before a consequential write. Without it, consequential writes are refused.
confirmTimeoutMs Number Optional. How long confirm may wait before the write is refused. Two minutes by default; 0 waits forever.
announce(report) void Optional. Called after every apply(), for an app-wide toast or log. A chat panel can read the report that apply() returns instead.

Directives

[clrContext]

Adds what only the application knows to the element it sits on (on an ng-container, the element around it). It is reported on that element's node in components, merged with what a component there publishes. Where both set the same key, the component's value wins. Standalone: import ClrContext, or ClrContextModule in an NgModule. CLR_CONTEXT_DIRECTIVES lists the directives.

Input Values Default Effect
clrContext String — What this part of the page is about, in plain words. It becomes the node's label.
clrContextType String the element's role, or 'group' What kind of UI it is.
[clrContextState] Object null Application state worth knowing, added to the node's state. Keep it small, and pass a new object when it changes.
[clrContextPublicKeys] String[] null The state keys untrusted callers may see. Without it they see none of this state (see Untrusted callers below). It does not affect what the component publishes, which lists its own.

Attributes

Hiding content

Password and file inputs, and inputs with autocomplete set to current-password, new-password, one-time-code or a cc- value, are always withheld. Mark other secrets, such as API tokens or private keys in plain text fields.

Attribute Effect
data-clr-context-redact The field, or every field inside the element, is still described (its label and type), but its value and the text it shows are never read or written. Exported as CLR_CONTEXT_REDACT_ATTRIBUTE.
data-clr-context-ignore The element and everything inside it is invisible to the engine. Put it on the chat panel itself, so the assistant does not describe its own conversation. Exported as CLR_CONTEXT_IGNORE_ATTRIBUTE.

Snapshot options

ClrContextSnapshotOptions. Set them for every snapshot with configure({ scope }), and pass them to a single call to change them for that call. Exclusion lists add up, so a call can only leave out more.

Option Default Effect
root 'page' The part of the page to describe. 'modal' describes only the open modal dialog, or the whole page when no dialog is open, so it can be set once for the whole application. Anything else is a CSS selector, such as 'main'.
excludeCategories [] Kinds of content to leave out: layout (header, navigation, footer, side panels), actions, forms, headings, collections, dialogs, status, images, text (paragraphs and other plain text), frames.
excludeSelectors [] CSS selectors for elements to leave out, with everything inside them. This only trims the snapshot; to keep something from agents, use data-clr-context-redact or data-clr-context-ignore.
maxComponents 300 The most nodes to describe. When it runs out, the rest of the page is left out and the snapshot has truncated: true.
maxItemsPerCollection 25 The most items to list per collection: rows, tabs, list items, options, menu items. 0 gives counts and the selection only.

Presets for scope: 'full' (the defaults), 'interactive' (no plain text, no layout) and 'minimal' (also counts instead of items, 150 nodes and root: 'modal').

Untrusted callers

The application's own code sees everything. window.clrContext() is untrusted, because the application does not control who calls it. Its callers get less:

  • No values the user entered or chose (typed text, selected options and rows, ticked boxes), unless the application sets shareFormValues. A withheld value is marked withheld: true.
  • No full URL or page title, only the route pattern such as clusters/:id, unless the application sets shareFullUrl.
  • Published state only under the keys listed in publicKeys. A key nobody listed stays private.
  • Only safe options: maxComponents, maxItemsPerCollection, excludeCategories, and root set to 'page' or 'modal'. Never selectors, and never more than the application allows.

Snapshot

What snapshot() returns and watch() emits. CLR_PAGE_CONTEXT_SCHEMA is its JSON Schema, for validating snapshots outside TypeScript.

ClrPageContext

Property Type Description
schemaVersion String The snapshot format's version. New fields can appear without it changing.
application ClrApplicationContext The application's id and version. The id is the page's host name when none is configured.
viewId String The view the user is on, when the application names it.
metadata Object What the application says about the current view.
enabled Boolean false when the application turned the engine off for this view; the snapshot then describes nothing on the page.
title, url String The document title and the current URL.
route ClrRouteContext With the router: the route pattern, its parameters, the query parameters and the route data.
availableRoutes ClrAvailableRoute[] With configure({ routes: true }): the routes the application can go to.
components ClrComponentContext[] What is on the page right now, as a tree, with the application's annotations on the nodes they describe.
regions ClrComponentContext[] What providers registered with ClrContextRegistryService said: context that no element shows. A provider still answering is a region of type 'clr-loading', and one that failed or was too slow is 'clr-unavailable'.
collectedAt String When the snapshot was taken, as an ISO timestamp.
truncated Boolean true when something was left out because a limit was reached.
focus 'modal' Present when the snapshot describes only the open modal dialog.

ClrComponentContext

One node of the tree.

Property Type Description
type String The ARIA role, such as grid, dialog or combobox. Plain text is text.
element String The tag, when it says more than the role, such as clr-side-panel or clr-modal for two dialogs.
label String Its accessible name, or the annotation's label.
state Object What is true of it now, such as expanded, selected, invalid, value, error or rows, the annotation's state, and what its component published (see Published values below).
children ClrComponentContext[] What it contains. A dialog's buttons are among its children.
ref String The id to pass to setValue and clear. Present only with a mutation policy, and only on fields that can be written.

Publishing from a component

For component authors: say what a component knows that its markup does not show. These live in @clr/angular/utils. An element holds one published context, so do not publish on an element that already publishes, such as a clr-datagrid; use a wrapper element.

Member Returns Effect
publishElementContext(host, callback) () => void The engine calls callback on every snapshot and merges its answer into the host's node. Returns a function to call on destroy.
publishElementMutator(host, mutator) () => void Makes a custom control writable by setValue. The ClrElementMutator has three functions: coerce(proposed) turns what the agent asked for into the model value, write(proposed) writes state that is not a form control, and read() reads the value back. All are optional.
contextText(element, skip?) string The text an element shows, leaving out hidden and redacted parts. Use it to label rows or options from their content.
normalizeContextText(text, lowercase?) string Collapses whitespace and lowercases, to compare labels the way the engine does.
usableSelectors(root, selectors) string Joins the valid selectors into one and drops invalid ones.
CLR_CONTEXT_DEFAULT_MAX_ITEMS number How many items to list when the caller sets no limit: 25.

ClrPublishedContext

What publishers, extractors and providers return: a ClrComponentContext with one more field.

Property Type Description
publicKeys readonly string[] The state keys untrusted callers may see. None by default. Each child lists its own, and each source (an annotation, a component) covers only its own state.

Published values

What Clarity components add to their node's state. Keys marked (value) are what the user entered or chose, so untrusted callers do not see them.

Component State
clr-datagrid totalRows, rows (each row's cells, such as esx-01 | ok; value), filteredColumns (value), hiddenColumns (value). When rows can be selected: selectionMode and selection (value).
clr-combobox multiSelect, options, value (value). While the list is narrowed to what the user typed, matchingOptions (value) replaces options. optionsPending or matchingOptionsPending while clrLoading is set.
clr-wizard stepCount, currentStepIndex, and steps, each with title, current, complete, error and navigable
clr-stepper-panel status: inactive, complete or error
clr-timeline-step status: not-started, current, processing, success or error
clr-tree-node expandable, and loading while children load
clr-alert severity
clr-file-input-container fileCount (value). The files themselves are never described.
clr-date-container The date is the input's value (value).
input[clrPassword] Described without its value.
