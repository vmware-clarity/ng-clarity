Most applications need only a few of these: ClrContextService to read the page, configure({ application }) to name the application, data-clr-context on a view's root to describe the view, and data-clr-context-redact for fields that hold secrets. Everything else is for finer control.

Services

ClrContextService

Reads the page and returns it as a snapshot. Nothing is cached: every snapshot reads the page as it is.

Member Returns Effect
configure(config) void Sets how the application wants its context read (see Configuration below). Call it once, at startup. A second call replaces the whole configuration, and a snapshot taken before it uses the defaults.
snapshot(options?) Promise<ClrPageContext> Describes the page as it is now. options apply over the configured scope (see Snapshot options below). It first waits for providers that answer with a promise, up to timeoutMs each.

Configuration

ClrContextConfig, passed to configure(). Every key is optional.

Key Default Effect
scope 'full' What every snapshot reads: a preset name or snapshot options (see Snapshot options below).
routes false Lists the router's routes in availableRoutes, so an agent can suggest a page that is not linked from the current one.
extractors [] Describe markup the engine cannot understand on its own, such as an element from another library with no role and no name. Each is a ClrContextDomExtractor: a selector and an extract(element, options) function. Its answer replaces the element and everything inside it.
timeoutMs 2000 How long a snapshot waits for each provider that answers with a promise. A provider that fails or is too slow appears as a region of type 'clr-unavailable'.
application the host name Names the application and its views, as a ClrContextApplicationOptions. See the table below.
views 'all' 'all' reads every view. 'enabled' reads only views that have metadata, and reports the rest as enabled: false with nothing about the page.
viewConfig [] Describes views without editing them: a list of ClrContextViewConfig, or the URL of a JSON file that holds it as { "views": [...] }. See View configuration below.
metadataOrigins [] Other origins that data-clr-context-url and a viewConfig URL may load from, such as 'https://help.example.com'. The page's own origin is always allowed.

application

Option Type Description
id String A stable id for the application, such as 'inventory'.
version String The application's version.
viewId () => string | null | undefined A function that returns the current view's id, called on every snapshot. Often not needed: put data: { viewId: 'vm-list' } on each route instead.
metadata () => object | null | undefined A function that returns a small object about the current view, called on every snapshot.

View configuration

Each entry in viewConfig matches by route pattern and/or selector. The first match applies.

Key Type Description
route String The route pattern, as route.path reports it, such as 'hosts/:id'.
selector String Matches while an element matching this CSS selector is on the page.
viewId String The view's id, used when nothing on the page or the route names one.
metadata Object What to say about the view. Metadata from the page wins over it.
enabled Boolean false means nothing on that view is read. true reads it with views: 'enabled' even without metadata.

ClrContextRegistryService

Adds context that no element shows, such as a workflow model held in a service. Register a ClrContextProvider, an object with a getClrContext() method, and the engine calls it on every snapshot. The answer appears in the snapshot's regions. Context about an element goes on the element with [clrContext] instead.

Member Returns Effect
register(provider) () => void Adds a provider and returns a function that removes it. getClrContext() returns a ClrPublishedContext, or null when there is nothing to say. It may also return a promise, which snapshot() waits for.
unregister(provider) void Removes a provider, typically in ngOnDestroy.

Directives

[clrContext]

Adds what only the application knows to the element it sits on (on an ng-container, the element around it). It is reported on that element's node in components, merged with what a component there publishes. Where both set the same key, the component's value wins. On a view's root, it describes the view instead (see View metadata below). Standalone: import ClrContext, or ClrContextModule in an NgModule. CLR_CONTEXT_DIRECTIVES lists the directives.

Input Values Default Effect
clrContext String — What this part of the page is about, in plain words. It becomes the node's label.
clrContextType String the element's role, or 'group' What kind of UI it is.
[clrContextState] Object null Application state worth knowing, added to the node's state. Keep it small, and pass a new object when it changes.

Attributes

Annotations in markup

The same as [clrContext], for markup not built with Angular, such as a same-origin frame or HTML from a server. [clrContext] wins when an element has both.

Attribute Effect
data-clr-context What this part of the page is about, like clrContext.
data-clr-context-type What kind of UI it is, like clrContextType.
data-clr-context-state State as a JSON object, like clrContextState.
data-clr-context-url Loads an annotation as JSON, { label, type, state }, from a URL on the page's origin or one listed in metadataOrigins. It is loaded once and read only on a view's root, where it describes the view.

The names are exported as CLR_CONTEXT_LABEL_ATTRIBUTE, CLR_CONTEXT_TYPE_ATTRIBUTE, CLR_CONTEXT_STATE_ATTRIBUTE and CLR_CONTEXT_URL_ATTRIBUTE.

View metadata

An annotation on a view's root describes the view, not a node. The view's root is the element a snapshot starts from: the body, the element root selects, or the open modal. Its ancestors count too, the inner one winning. The annotation's state, with its label, becomes the snapshot's metadata, and a viewId key in it names the view.

When several sources describe the same view, the most specific wins: the annotation itself, then data-clr-context-url, then application.metadata, then the matching viewConfig entry. The view id comes from the annotation, then application.viewId, then the route's data.viewId, then viewConfig. While a URL loads, or if it fails, the snapshot's metadataState is 'loading' or 'unavailable'.

Hiding content

Password and file inputs, and inputs with autocomplete set to current-password, new-password, one-time-code or a cc- value, are always withheld. Mark other secrets, such as API tokens or private keys in plain text fields.

Attribute Effect
data-clr-context-redact The field, or every field inside the element, is still described (its label and type), but its value and the text it shows are never read. Exported as CLR_CONTEXT_REDACT_ATTRIBUTE.
data-clr-context-ignore The element and everything inside it is invisible to the engine. Put it on the chat panel itself, so the assistant does not describe its own conversation. Exported as CLR_CONTEXT_IGNORE_ATTRIBUTE.

Snapshot options

ClrContextSnapshotOptions. Set them for every snapshot with configure({ scope }), and pass them to a single call to change them for that call. Exclusion lists add up, so a call can only leave out more.

Option Default Effect
root 'page' The part of the page to describe. 'modal' describes only the open modal dialog, or the whole page when no dialog is open, so it can be set once for the whole application. Anything else is a CSS selector, such as 'main'.
excludeCategories [] Kinds of content to leave out: layout (header, navigation, footer, side panels), actions, forms, headings, collections, dialogs, status, images, text (paragraphs and other plain text), frames.
excludeSelectors [] CSS selectors for elements to leave out, with everything inside them. This only trims the snapshot; to keep something from agents, use data-clr-context-redact or data-clr-context-ignore.
maxComponents 300 The most nodes to describe. When it runs out, the rest of the page is left out and the snapshot has truncated: true.
maxItemsPerCollection 25 The most items to list per collection: rows, tabs, list items, options, menu items. 0 gives counts and the selection only.

Presets for scope: 'full' (the defaults), 'interactive' (no plain text, no layout) and 'minimal' (also counts instead of items, 150 nodes and root: 'modal').

Snapshot

What snapshot() returns. CLR_PAGE_CONTEXT_SCHEMA is its JSON Schema, for validating snapshots outside TypeScript.

ClrPageContext

Property Type Description
schemaVersion String The snapshot format's version. New fields can appear without it changing.
application ClrApplicationContext The application's id and version. The id is the page's host name when none is configured.
viewId String The view the user is on, when the application names it.
metadata Object What the application says about the current view.
metadataState 'loading' | 'unavailable' Present while metadata from a URL is loading, or when it could not be loaded.
enabled Boolean false when the application turned the engine off for this view; the snapshot then describes nothing on the page.
title, url String The document title and the current URL.
route ClrRouteContext With the router: the route pattern, its parameters, the query parameters and the route data.
availableRoutes ClrAvailableRoute[] With configure({ routes: true }): the routes the application can go to.
components ClrComponentContext[] What is on the page right now, as a tree, with the application's annotations on the nodes they describe.
regions ClrComponentContext[] What providers registered with ClrContextRegistryService said: context that no element shows. A provider still answering is a region of type 'clr-loading', and one that failed or was too slow is 'clr-unavailable'.
collectedAt String When the snapshot was taken, as an ISO timestamp.
truncated Boolean true when something was left out because a limit was reached.
focus 'modal' Present when the snapshot describes only the open modal dialog.

ClrComponentContext

One node of the tree.

Property Type Description
type String The ARIA role, such as grid, dialog or combobox. Plain text is text.
element String The tag, when it says more than the role, such as clr-side-panel or clr-modal for two dialogs.
label String Its accessible name, or the annotation's label.
state Object What is true of it now, such as expanded, selected, invalid, value, error or rows, the annotation's state, and what its component published.
children ClrComponentContext[] What it contains. A dialog's buttons are among its children.

Publishing from a component

For component authors: say what a component knows that its markup does not show. These live in @clr/angular/utils. An element holds one published context, so do not publish on an element that already publishes; use a wrapper element.

Member Returns Effect
publishElementContext(host, callback) () => void The engine calls callback on every snapshot and merges its answer into the host's node. Returns a function to call on destroy.
usableSelectors(root, selectors) string Joins the valid selectors into one and drops invalid ones.
CLR_CONTEXT_DEFAULT_MAX_ITEMS number How many items to list when the caller sets no limit: 25.

ClrPublishedContext

What publishers, extractors and providers return: a ClrComponentContext whose children are published contexts too.

Lower-level helpers

Member Effect
clrDiffContext(previous, current) What changed between two snapshots, as a ClrContextChange. clrIsEmptyContextChange(change) says whether nothing did.
CLR_CONTEXT_PRESETS, CLR_CONTEXT_DEFAULT_OPTIONS The options each preset stands for, and the defaults.
CLR_CONTEXT_CATEGORIES The roles each excludeCategories entry stands for.
CLR_CONTEXT_LOADING_TYPE, CLR_CONTEXT_UNAVAILABLE_TYPE 'clr-loading' and 'clr-unavailable', the region types for a provider that has not answered.
ClrContextRegistryService.collect(options?) What the registered providers say now; collectAsync(options?) waits for the ones that answer with a promise. The service calls these itself.
CLR_CONTEXT_HIDDEN_SELECTOR A selector for what the engine treats as hidden, for publishers that label things from their content.
