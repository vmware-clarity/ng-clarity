Services

ClrContextEngineService

Root-provided. Builds snapshots on demand and owns the global accessor, the way context leaves the application.

Member Returns Effect
getSnapshot(options?) ClrPageContext Describes the page as it is at this moment. Nothing is cached, so a snapshot cannot report UI that has been closed, destroyed or navigated away from.
registerDomExtractor(extractor) () => void Teaches the collector about markup that carries neither an ARIA role nor an accessible name. Returns a function that removes it again.
enableGlobalAccess(propertyName?, options?) void Exposes window.clrContext() for agents driving the browser. Because any script on the page can call it, the caller is treated as untrusted: only the options in CLR_CONTEXT_UNTRUSTED_OPTION_KEYS are honoured (budgets, categories, roles, focus, collection mode — never selectors), each held to what the application allows through options here and provideClrContextOptions, and to the defaults wherever neither says: a caller cannot turn on includeRoutes or raise maxComponents past them. What the user entered — typed values, chosen options, ticked boxes, pressed toggles, selected rows — is withheld unless shareFormValues is set, and the page's address is reduced to its route pattern — links to the application to the pattern they match, links elsewhere and frames to their origin, mailto: links to their scheme — and the document title withheld — the page's, and a frame's state.title — unless shareFullUrl is set. The application's own clrContext annotations are shared as they are. Descriptions — helper and validation text — are still shared: keep what they say free of the value, or mark the field data-clr-context-redact.
disableGlobalAccess() void Removes the global accessor.

ClrContextTrackerService

Root-provided. Turns the pull-based engine into a stream for consumers that always want the current page.

Member Type Effect
context$ Observable<ClrPageContext> Emits whenever the page context actually changes, replaying the most recent snapshot to new subscribers until the service is destroyed.
currentContext ClrPageContext | null The most recent snapshot, or null before tracking starts.
isTracking Boolean Whether the tracker is watching the page. The tracker is shared: a consumer that only wants to look can check this and leave starting and stopping to whoever owns tracking.
track(options?) Observable<ClrPageContext> The page context, tracked for as long as anyone subscribes: the first subscription starts tracking when nothing else has, and the last one to end stops it, so consumers that come and go share one tracker without stopping each other's. With options, tracking restarts with them; without, running tracking is joined as it is. There is one tracker, so its options apply to every consumer.
start(options?) void Takes a snapshot immediately, then watches the DOM for changes and input / change for typing. Calling it again restarts with the new options. Each snapshot walks the page, taken once the page has been quiet for debounceMs and at most every maxWaitMs while it keeps changing; on a large page, narrow it with rootSelector or a smaller preset.
stop() void Stops tracking. The last emitted context stays available.
refresh() void Takes a snapshot immediately and emits it.
changes$ Observable<ClrContextChange> Emits, alongside every context$ emission, what changed since the previous one — nodes added, removed and changed, and whether the route, title or annotations moved — so a conversation can send the difference rather than the whole page. clrDiffContext(previous, current) is the same comparison as a function.

ClrContextRegistryService

Root-provided. Holds whatever can contribute application knowledge to a snapshot. Providers are polled at snapshot time and nothing is stored, so an annotation cannot go stale.

Member Returns Effect
register(provider, element?) () => void Registers a ClrContextProvider. Returns a function that unregisters it. Given the element the annotation sits on, the annotation follows that element's fate: left out when the element is hidden, ignored or outside the snapshot root, and reported without its state inside a redacted region. [clrContext] passes its host element.
unregister(provider) void Removes a provider, typically from ngOnDestroy.

Directives

[clrContext]

Annotates a region with the knowledge only the application has. Ships in ClrContextModule.

Input Values Default Effect
clrContext String — What this region is about, in words an agent can use.
clrContextType String 'region' The kind of UI this annotation describes.
[clrContextState] Object null Application state worth knowing, read at snapshot time rather than stored, so it is never out of date.

Attributes

Attribute Effect
data-clr-context-ignore The element and everything inside it is invisible to the engine: never described, and its DOM changes and annotations never trigger a re-scrape. Put it on UI that renders the context, so a panel cannot describe itself or loop. Exported as CLR_CONTEXT_IGNORE_ATTRIBUTE.
data-clr-context-redact The control, or every control in the region, is still described — label, type, what it permits — but its value is never reported, and the text the region shows is left out. A component inside publishes only that it is redacted: a datagrid reports neither its rows nor its selection. An annotation inside is reported without its state. Addresses count as content: a link or frame inside keeps its name but not where it points. A name taken from what an element shows is content too, so inside the region a link or button is named only by what its author gave it — a label, aria-label, a title. An item inside a list, tab list, menu or grid that is otherwise readable is counted, but its name is withheld. Exported as CLR_CONTEXT_REDACT_ATTRIBUTE.
CLR_CONTEXT_HIDDEN_SELECTOR What the engine treats as not on the page — hidden, aria-hidden="true", inert or data-clr-context-ignore, and everything inside — as one selector, for a component that publishes context and must agree with the engine about what an agent may see.
CLR_CONTEXT_WITHHELD_SELECTOR Everything CLR_CONTEXT_HIDDEN_SELECTOR matches, and regions marked data-clr-context-redact: what a component that labels something from its content — a row by its cells, an option by its text — leaves out of that label. CLR_CONTEXT_IGNORE_SELECTOR and CLR_CONTEXT_REDACT_SELECTOR match the two attributes on their own.
CLR_CONTEXT_EDITING_HOST_SELECTOR An editing host — contenteditable in any spelling but false. What it holds was typed by the user, a value, so it is part of CLR_CONTEXT_WITHHELD_SELECTOR and never read into a label.

Snapshot options

ClrContextSnapshotOptions. Defaults are in CLR_CONTEXT_DEFAULT_OPTIONS, which, like CLR_CONTEXT_PRESETS and CLR_CONTEXT_CATEGORIES, is frozen: spread it into an object of your own to change it.

Option Default Effect
maxTextLength 100 Longest any single string may be. Anything longer is truncated with an ellipsis.
maxItemsPerCollection 25 Most items reported per collection — rows, tabs, list items, options, menu items.
maxComponents 300 Most components described in total. The walk stops when the budget is spent, so a low value drops whatever comes last in the document — and the snapshot then carries truncated: true.
includeDomComponents true Whether to describe the rendered page at all. Turn it off for route and annotations only.
includeText true Whether visible text that carries no role — a paragraph, a card's body — is reported as text nodes, so what the page says reaches the agent along with what it can do.
includeFrames true Whether embedded frames are reported: a same-origin frame as a frame node with the frame's content as children, a cross-origin frame as a frame node without children. false leaves out every frame, same-origin or not.
includeRoutes false Whether to list the routes the application can navigate to (availableRoutes: path patterns from the router configuration, with titles where named), so an agent can propose going somewhere the page does not link to. The application performs the navigation. The list is bounded by maxItemsPerCollection, never to fewer than 50 routes.
excludeCategories [] Kinds of content to leave out by name — layout (header, navigation, footer, side panels), actions, forms, headings, collections, dialogs, status, images, text, frames. Each expands to the roles it covers (CLR_CONTEXT_CATEGORIES).
excludeRoles [] Roles whose whole subtree is left out — ['navigation', 'banner', 'contentinfo'] drops the header, navigation and footer that repeat in every snapshot.
excludeSelectors [] CSS selectors for elements to leave out with their subtree. Their text is also kept out of other elements' names, descriptions and summaries. Use them to make snapshots relevant. To keep content from agents, mark it data-clr-context-ignore or data-clr-context-redact: a caller the application does not control cannot set selectors.
rootSelector whole document CSS selector for the element(s) to describe instead of the whole document, e.g. main.
maxDepth 0 (unlimited) Deepest nesting of described nodes, counted from the top.
focus 'page' 'modal': while a modal dialog is open, describe only the dialog; the snapshot then carries focus: 'modal'.
collectionItems 'all' 'summary': collections report counts and current selection only, without item, option or tab lists.

Application-wide options and presets

provideClrContextOptions(preset | options, overrides?) sets the options every snapshot starts from — the engine, the tracker and the global accessor all read the CLR_CONTEXT_OPTIONS token — with per-call options applied over them. Presets: 'full' (the defaults), 'interactive' (no prose, no layout: navigation, banner, footer and side panels) and 'minimal' (no prose or layout, summary collections, shorter text, a lower budget, modal focus). clrContextPreset(name, overrides?) returns a preset with overrides for a single call; exclusion lists in the overrides add to the preset's, so an override can only narrow it further.

Context shape

ClrPageContext

Property Type Description
title String The document title. The global accessor receives an empty title, unless the application sets shareFullUrl.
availableRoutes ClrAvailableRoute[] With includeRoutes: the routes the application can navigate to — path, title, and lazy for a route whose children are not loaded yet.
url String The current URL. The global accessor receives only the origin and the route pattern, unless the application sets shareFullUrl.
route ClrRouteContext Present when the application uses the router: the path pattern, route and query parameters, and the JSON-serializable part of the route data.
regions ClrComponentContext[] What the application said about itself, through clrContext.
components ClrComponentContext[] What is rendered right now, as a tree.
collectedAt String ISO timestamp of the moment the snapshot was taken.
truncated Boolean Present and true when something was left out for size: the maxComponents budget ran out, a grid holds controls in more cells than maxItemsPerCollection lists, or the page nests deeper than 512 elements or holds more than 25,000 for one walk to read.
focus 'modal' Present when focus: 'modal' narrowed the snapshot to the open modal dialog.

ClrComponentContext

Property Type Description
type String The ARIA role describing what this is — grid, dialog, tablist, combobox. The same word whatever library rendered it.
element String The tag that rendered it, when that says something the role cannot — so a clr-side-panel and a clr-modal stay distinguishable while both being dialogs.
label String Its accessible name.
state Object What is true of it right now: expanded, selected, invalid, sort, value, options, description, and redacted where a value is withheld.
children ClrComponentContext[] What it contains, where that structure matters. A button or link is a node here, not a separate top-level list: to find what a dialog offers, read the dialog's own children.

Publishing from a component

A component that knows more than its markup shows can say so. The contract lives in @clr/angular/utils rather than here, so publishing costs a component nothing but one import.

Member Returns Effect
clrPublishElementContext(host, callback) () => void Publishes a callback on the host element, returning the teardown to run on destroy. The teardown removes only the callback it published, so republishing is safe. What a component publishes wins over what the markup showed — except a value the engine withheld as sensitive, which is removed again. Inside a data-clr-context-redact region nothing published is merged, and an element that publishes a label is described without one, since the name its markup gives it is the one the component meant to replace.
clrContextText(element, skip?) string The text an element shows, as a publisher may report it: text inside a redacted or ignored descendant, text hidden from assistive technology and text hidden by style are left out, and block-level parts read as separate words. Use it to label rows or options from their content, so a value the application withheld never reaches a label.
clrNormalizeContextText(text, lowercase?) string Text as the engine compares it — whitespace collapsed, and lowercased unless told otherwise — so a publisher and the engine agree on whether two labels are the same.
clrUsableSelectors(root, selectors) string The selectors root's document accepts, joined into one, or ''. A publisher given excludeSelectors uses it so that one invalid entry does not throw, nor drop the others.
CLR_ELEMENT_CONTEXT_PROPERTY string The element property clrPublishElementContext sets, for tooling other than this engine that reads them.
CLR_CONTEXT_DEFAULT_MAX_ITEMS number How many items a publisher lists when the caller gives no budget: the engine's default maxItemsPerCollection, 25.

What components publish

State a Clarity component adds to its node, beyond what the accessibility tree says. Keys marked as values — value, selection, rows, filteredColumns, hiddenColumns, fileCount, matchingOptions, redactedMatchingOptions, matchingOptionsPending and matchingOptionCount — are withheld from the global accessor unless the application shares form values, and so is the state any node reads from the accessibility tree to say what the user chose: selected, checked, pressed and selectedRows.

Component State
clr-datagrid totalRows (paginated total), filteredColumns (value), hiddenColumns (value); when rows can be selected, selectionMode (single or multi), rows (each row's cells, the names its rows go by; value) and selection (value)
clr-combobox
  • multiSelect
  • options and redactedOptions (how many options are withheld)
  • matchingOptions and redactedMatchingOptions (values), in their place while the list may be narrowed to what the user entered:
    • while *clrOptionItems filters it by the text in the input;
    • when the application listens to clrInputChange, while text is in the input, a picked option's label included;
    • for such a combobox, also whenever there is any list, written-out options included, since it may answer earlier text or a search kept from an earlier instance.
  • matchingOptionsPending (value) while clrLoading says a search for the text in the input is running; optionsPending while it is set otherwise, as on opening an empty combobox or after clearing it
  • optionCount, or matchingOptionCount (value) while narrowed, in place of the lists in a summary snapshot, counting redacted options too
  • optionsAvailable: false while the list is empty and not narrowed, as before a search loads it
  • value (value)
clr-wizard stepCount, currentStepIndex, steps (each with its index, title as its stepnav item shows it, current, complete, error and navigable), while the wizard is open
clr-stepper-panel status: inactive, complete or error
clr-timeline-step status: not-started, current, processing, success or error
clr-tree-node expandable, and loading while children load
clr-alert severity, while the alert is shown
clr-file-input-container fileCount (value), redacted (always: the files themselves are never described, and the file list is left out), disabled when the input is disabled; helper, error and success text are kept
clr-date-container The calendar toggle's name without the selected date, which the date input reports as its value (value); inside a data-clr-context-redact region the toggle is described without a name. The open calendar is not described
input[clrPassword] Nothing of its own: the input is marked data-clr-context-redact, so it is described without its value
