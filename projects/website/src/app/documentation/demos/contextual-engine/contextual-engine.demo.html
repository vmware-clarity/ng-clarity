The @clr/ai package gives AI agents structured, always-current context about the page your application is showing: the active route, the components rendered right now and their state, the actions currently available, and any semantic annotations the application provides.

@clr/ai is a standalone package that does not depend on @clr/angular: Clarity components are described by reading the rendered DOM, so the engine works alongside any Clarity version — and, through custom extractors and a framework-agnostic postMessage protocol, with other UI libraries and with UI embedded in iframes, such as chat assistants.

Installing

The only peer dependencies are @angular/common, @angular/core, @angular/router and rxjs — already present in every Angular application.

ClrContextualEngineService.getSnapshot() computes a snapshot on demand from the live DOM and live registrations. Nothing is cached, so a snapshot can never describe UI that has been closed, destroyed or navigated away from.

Keeping a live page context

Consumers that always want the context of the page the user is currently on — an AI chat panel, for example — subscribe to ClrContextTrackerService. It watches the DOM with a MutationObserver (created outside the Angular zone, so it triggers no change detection) and re-scrapes after a quiet window of debounceMs (default 300), bounded by maxWaitMs (default 2000) for pages that never go quiet. An emission happens only when the context actually changed, and each emission is a complete fresh snapshot.

Mark UI that renders the context with the data-clr-context-ignore attribute (exported as CLR_CONTEXT_IGNORE_ATTRIBUTE). Such regions are invisible to the engine end to end: the collector never describes them and the tracker ignores their mutations, so a panel re-rendering the context cannot re-trigger tracking or describe itself into the page context.

Annotating the application

The DOM only knows what is on the page. The clrContext directive lets the application add the why — knowledge only it has. Annotations register when the element appears, unregister when it is destroyed, and are read at snapshot time, so they are never stale.

The protocol is two plain JSON messages over postMessage (see CLR_CONTEXT_PROTOCOL), so the embedded page needs neither Angular nor Clarity. Requests are answered per frame and per request with a freshly computed snapshot — context is never broadcast.
