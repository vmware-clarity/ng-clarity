Column Actions

A clr-dg-column-actions inside a clr-dg-column puts a menu at the trailing edge of that column's header and gathers what the column can do into one control, instead of a row of icons growing across the header.

The menu only offers what the column can actually perform, so it never shows a dead option. A sortable column gets Sort Ascending and Sort Descending, and Clear Sort once it is sorted and clrDgDisableUnsort allows it. A column with a filter gets Filter Column. A column with clrDgPinnable gets Pin Column - see Pinnable Columns.

Nothing that worked before goes away: the column title stays sortable, so the menu is an addition rather than a replacement.

The Filter Moves Into the Menu

A column that has a filter normally shows its own filter icon in the header. While the menu is present that icon is dropped and Filter Column takes over, so the header keeps one control per column rather than two. Choosing it opens the same filter, anchored to the menu item rather than to the header.

The menu trigger also takes over showing that the column is filtered, which the icon used to do - it carries a badge while a filter is applied.

Set clrDgKeepFilterInHeader to keep the filter icon where it was. The menu then drops its Filter Column action in exchange, so a column always offers one way to reach its filter and never two - either the icon in the header or the action in the menu.

Adding Your Own Actions

Anything projected into clr-dg-column-actions is appended after the built-in items. Mark each one with clrDgColumnAction, which gives it the styling of a menu item, a place in the arrow key order, and the same close-on-click behaviour as the built-in items.

clrDropdownItem cannot be used for this. Injection resolves from where a node is declared rather than where it ends up rendered, so an item projected into the menu sits outside the injector of the dropdown in that component's template and cannot reach it. clrDgColumnAction registers with the component it is projected into instead, which does resolve, and lets that component hand it to the dropdown.

Use clrDisabled for an action that does not apply right now. It stays in the menu, announced as disabled and skipped by activation, rather than disappearing and moving the items under it. The built-in items work the other way round - they are left out entirely until the column can act on them - so this is a choice you make for your own actions rather than a pattern to match.

Use clrCanClosePopover set to false for an action that moves the column the menu belongs to. The menu is anchored to a trigger that travels with the column, so leaving it open where the column used to be would be worse than closing it - with this it is re-anchored to the trigger in the column's new place instead. This is what the built-in Pin Column action does.

A projected action renders its own cds-icon, so register whatever shape it names.

Accessibility

The trigger is labelled with the column it belongs to, so a screen reader announces which column's actions are being opened rather than repeating the same label down the header. The menu is a menu of menuitems, walkable with the arrow keys, and each item is activated with space or enter. Items projected with clrDgColumnAction join that order, so an application action is reachable the same way as a built-in one.
