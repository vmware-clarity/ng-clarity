Pinnable Columns

A clr-dg-column with clrDgPinned is rendered to the left of the scrollable columns and stays visible while the rest of the datagrid is scrolled horizontally. Useful to keep the column that identifies a row in view while the user reads the columns further to the right.

Pinning More Than One Column

There is no limit on how many columns you can pin. Pinned columns keep the order they are declared in and are placed after the built-in row controls - selection, row actions and the expand caret - which always stay at the very left. Pinning a column does not move it in the declaration order of the others, so the remaining columns keep their relative order as well.

Maximum Width of Pinned Columns

While there is no limit on the number of pinned columns, there is one on their total width. The pinned region - the built-in row controls together with the pinned columns - is capped at 85% of the visible width of the datagrid, so the scrollable columns always keep a remainder. The user can therefore always see that the datagrid scrolls sideways and can reach the rest of the data.

When the pinned columns ask for more than the cap, they shrink to fit it instead of spilling past it. They give up room in proportion to the widths you set, so a wide pinned column loses more than a narrow one, and no column shrinks below the minimum width of a datagrid column. Pinned columns that already fit are left exactly at the widths you gave them.

The cap is a share of the current width of the datagrid, so it applies just as much when the datagrid becomes narrower as when a column becomes wider - a layout that fits on a wide screen shrinks its pinned columns on a small one. Because the columns shrink instead of the pinned state changing, clrDgPinned is never written back to and a column you pinned stays pinned.

The share is the --clr-datagrid-pinned-columns-max-width CSS custom property and defaults to 85cqi. Override it with a cqi value rather than a percentage: cqi resolves against the visible width of the datagrid, while a percentage would resolve against the full scrollable width of a row and so would not cap anything once the columns overflow.

Pinned Columns in Expandable Rows

An expandable row whose clr-dg-row-detail holds one clr-dg-cell per column is laid out in the same columns as the row above it, and the cells of the pinned columns are pinned along with them. The detail then scrolls sideways together with the row, and the cell that identifies it stays in view just like the one in the row.

This applies whether the detail is added to the row or replaces it with clrDgReplace. It only happens when the cell count matches the column count: a detail with any other number of cells is free-form content and is left exactly as you wrote it, as is a detail in a datagrid with no pinned columns. Note that a matching detail can only be laid out in columns if its cells are its direct children - anything you put between them keeps its own place and is not moved with them.

Letting the User Pin Columns

Add clrDgPinnable to let the user pin and unpin the column from inside the datagrid instead of the application driving it. It offers Pin Column in the column's actions menu, so the column also needs a clr-dg-column-actions to render that menu - the label and its icon follow the state, a pin while the column is loose and an unpin once it is pinned.

The two inputs are independent and do different jobs. clrDgPinnable only adds the control; the pinned state itself stays on clrDgPinned. A column can therefore be pinned without being user-pinnable, and pinnable without starting out pinned.

When the user pins or unpins from the menu, the column reports the new state through clrDgPinnedChange. Bind both halves with [(clrDgPinned)] so the application follows along - the example below uses it to list which columns are pinned. A one-way [clrDgPinned] binding would write its old value straight back on the next change detection, and the action would appear to do nothing.

The menu stays open after pinning, so the action that undoes it is right there, and it follows the column as it moves into the pinned region rather than being left behind.
