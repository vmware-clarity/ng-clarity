Pinnable Columns

A column with clrDgPinned is rendered to the left of the scrollable columns and stays visible while the rest of the datagrid is scrolled horizontally. Use it to keep the column that identifies a row - a name or an ID - in view while the user reads the columns further to the right.

The input goes on the clr-dg-column component itself. The cells follow their column automatically, so there is nothing to change on clr-dg-cell.

Pinning More Than One Column

There is no limit on how many columns you can pin. Pinned columns keep the order they are declared in and are placed after the built-in row controls - selection, row actions and the expand caret - which always stay at the very left. Pinning a column does not move it in the declaration order of the others, so the remaining columns keep their relative order as well.

Changing the Pinned State at Runtime

clrDgPinned can be bound to an expression, so a column can be pinned and unpinned while the datagrid is on screen. Scroll the datagrid below sideways and then change the checkboxes.

Considerations

  • Pinned columns take space away from the scrollable ones. Since there is no upper bound on how much of the datagrid they can occupy, pin only the columns a user needs to keep their place, and give them explicit widths.
  • The detail pane shows a single, full width column, so there is nothing left to scroll. Pinning is suspended for as long as the pane is open and restored when it closes. The clrDgPinned input itself is not changed.
  • Arrow key navigation follows the columns in the order they appear on screen, so pinning a column also moves it in the keyboard order.
