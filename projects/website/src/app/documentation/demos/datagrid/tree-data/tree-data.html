Tree Data

Use tree data when the rows have rows of their own, like folders and files. Children show below their parent, indented, in the same columns, and they can be sorted, selected and opened in the detail pane like any other row. The datagrid becomes an ARIA treegrid.

To render a tree, put *clrDgTreeItems on the row instead of *clrDgItems. It takes the top-level items and a getChildren function, which returns the children of an item as an array, a Promise or an Observable. The function is called the first time a row is expanded, and the children are kept after that. Rows are told apart with [clrDgItemsIdentityFn]: give the datagrid one that is unique across the whole tree, or a refresh that returns new objects collapses every row and clears the selection.

Expanding rows

Like a tree node, a row offers the expand toggle until its children come back empty. Set [clrDgExpandable] to false on the rows that cannot have children, so they never show the toggle. [(clrDgExpanded)] binds whether a row is expanded, and reports the rows the user expands or collapses. On the toggle, the Right arrow key expands the row and Left collapses it.

The toggle and the indentation are in the first column. To put them in another column, add clrDgTreeToggle to it.

Sorting and pagination

The top-level items work like the items of a server-driven datagrid: the datagrid emits (clrDgRefresh) when the user sorts or changes the page, and the application sends back the items of that page in order. The datagrid sorts the children itself, with the comparator of the column. Children that were loaded are kept while their parent is on another page.

Selection

Every row can be selected on its own. With cascadeSelection: true and multi-selection, selecting a row also selects its loaded descendants, and a row is selected when all of its children are, like in the tree view. Children that load later come in selected.

Data that is already loaded

When the whole tree is already in the data, return the children from getChildren as an array. They are shown as soon as the row is expanded, without a loading state. Set [clrDgExpandable] from the data, so the rows without children never show the toggle.

Reloading children

When the children of a row change on the server, call reloadTreeChildren(item) on the datagrid to fetch them again. Without an item, it fetches the children of the whole tree again. If getChildren fails, the row collapses so the user can try again; handle the error in the function to tell the user what happened.

Expanding and collapsing all rows

Call expandAllTreeRows() or collapseAllTreeRows() on the datagrid from your own buttons. Expanding all rows fetches the children of every level as the rows are shown, and the rows that come in afterwards, on any page, come in expanded too until the user collapses a row. (clrDgExpandedChange) reports the rows that expand all opens among the rows on display, not the ones it opens later. It reports every collapsed row, and a row that closes again because its children failed to load or came back empty.

Virtual scrolling

For large trees, use [clrVirtualTreeOf] on the virtual scroll template instead of [clrVirtualRowsOf], with [clrVirtualTreeGetChildren] and [clrVirtualTreeCascadeSelection]. Only the rows in view are rendered, however many rows are expanded.

Considerations

  • Do not combine tree data with expandable rows (clr-dg-row-detail) or nest datagrids. Use the detail pane to show more about a row.
  • Filters are sent with (clrDgRefresh) for the top-level items; the datagrid does not filter children.
