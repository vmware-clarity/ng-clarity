Filters (appfx-datagrid-filters from @clr/addons/datagrid-filters) is a filter bar with a quick search input and advanced filter pills. It only emits the search term and the active filters; the host applies them to its data.

When to use it standalone

Inside Advanced Datagrid the filter bar is built in. appfx-datagrid only passes on filterMode, filterableProperties, searchTermChange and advancedFilterChange. Place appfx-datagrid-filters yourself when you host it outside that grid, for example over a clr-datagrid, or when you need presetFilters, predefinedFilters, semiPredefinedFilters, toggleFilters or two-way [(propertyFilters)].

Modes

  • Quick: only the quick search input.
  • Advanced: quick search and advanced filters; the user switches between them.
  • Advanced only: only the advanced filter pills.
  • Combined: quick search and filter pills are shown and applied together. The host combines searchTermChange and propertyFiltersChange with AND, and Clear all clears both.

Filter pills

  • Opening a pill edits its criteria in a popover. Changes are applied only on Apply; Cancel, Escape and outside clicks discard them.
  • Clear filter returns a predefined pill to its empty state; user-added filters can be removed. Clear all clears all criteria and removes user-added pills while keeping predefined pills. Hide only hides user-added pills. Empty pills are not emitted.
  • Add filter uses a searchable field combobox. Existing pills keep their field locked while editing.
  • String and numeric filters support any number of conditions joined by one shared AND or OR operator. Add condition appends a row; set singleCondition to limit a field to one condition.
  • Active pills show the first condition and +N for additional conditions.

Field precedence

Each field can be used only once per filter bar. Fields are claimed from left to right: predefinedFilters first, then semiPredefinedFilters, then toggleFilters (the first toggle per field wins). Later entries for a claimed field are ignored with a console warning, and claimed fields are not offered in Add filter.

Semi-predefined fields only support picking options. A preset or propertyFilters entry for such a field must be one or more Equals conditions on option keys combined with OR; any other filter on the field is removed with a console warning.

Keeping filters in sync

  • [(propertyFilters)] holds the active filters, toggles that are ON included. A new value replaces the active filters; a filter with exactly a toggle's criteria turns that toggle ON. The filter bar copies the array and never changes it.
  • Setting propertyFilters does not emit propertyFiltersChange, so passing the emitted value back does not loop. The exception is a filter on a semi-predefined field that had to be removed; the corrected list is emitted.
  • presetFilters are applied once, at start-up. For the same field a preset wins over a propertyFilters filter. If the start-up result differs from what was passed in, propertyFiltersChange emits it once, after the first change detection.
  • Switching to quick mode clears the filters and emits an empty array.
  • Keep PropertyFilter.editorState when storing filters in memory. It restores editor choices the criteria cannot express, such as Last week.

Date-time and empty values

  • Date-time filters emit local date-times followed by the local UTC offset, e.g. 2026-03-29T00:00:00+02:00.
  • Equals a day is emitted as >= that day 00:00 AND < next day 00:00; a custom range ends before the midnight after its end date. A day always runs from midnight to the next midnight, also on daylight saving days (23 or 25 hours).
  • Last day, Last week and Time span count back a fixed length from now.
  • Is empty emits value: undefined; check the operator before the value.

Code & Examples

All examples share these property definitions and print the emitted filters below the bar.

Filter modes

Switch between Quick, Advanced, Advanced only and Combined.

Predefined filters

predefinedFilters keeps pills visible in the given order, even without criteria. Initial values come from presetFilters.

Semi-predefined filters

semiPredefinedFilters shows enum fields as a label followed by option pills. Selected options are combined with OR and applied immediately.

Toggle filters

toggleFilters shows ready-made filters as on/off pills. ON applies the filter as configured.

Two-way binding

Use [(propertyFilters)] to restore a saved view or a URL. Setting the value from the host does not emit propertyFiltersChange. Presets win over propertyFilters at start-up, and the start-up result is emitted once when it differs from what was passed in. The saved view below also turns the "Powered On" toggle ON.

Date-time filters

Restore an Equals a day filter, a custom range, or Last week. Relative operators such as Last week cannot be recovered from the criteria, so the filter carries editorState: { operator: ComparisonOperator.LastWeek }. Emitted values are local date-times followed by the UTC offset, and a day runs from midnight to midnight, also on daylight saving days.

Property definitions

A complete component that configures every property definition: String, Numeric (with a unit), Enum (single and multi select, searchable), DateTime and User, with the user service the User filter needs.

API Reference

appfx-datagrid-filters

Property Input/Output Type Description
filterMode Input FilterMode Quick, Advanced, AdvancedOnly or Combined.
filterableProperties Input FilterablePropertyDefinition[] Properties used for advanced filtering: String, Numeric, Enum, DateTime and User property definitions.
presetFilters Input PropertyFilter[] Filters applied when the filter bar starts. Read once; later changes are ignored.
predefinedFilters Input FilterablePropertyDefinition[] Properties whose pills stay visible without active criteria. Defaults to an empty array.
semiPredefinedFilters Input EnumPropertyDefinition[] Enum fields shown as a label followed by option pills, combined with OR.
toggleFilters Input PropertyFilter[] Ready-made filters shown as on/off pills.
propertyFilters Input PropertyFilter[] The active filters, toggles that are ON included. Supports [(propertyFilters)].
searchTermChange Output EventEmitter<string> Emits the quick search term on Enter and every 2 seconds while the user types.
propertyFiltersChange Output EventEmitter<PropertyFilter[]> Emits the active filters when the user changes them, and once at start-up when presets or clean-up change what was passed in.

UserPropertyDefinition requires a provided DatagridFiltersUserService. Localize the texts by providing DatagridFiltersStrings.

PropertyFilter

One filter pill: its criteria and how they are combined.

Property Type Description
criteria PropertyPredicate[] The conditions of the filter.
operator LogicalOperator How the conditions are combined: AND or OR.
editorState FilterEditorState Optional. Set by the built-in editors so a filter can be edited again, e.g. to keep Last week. Keep it when storing filters in memory. Not needed for host-built filters.

PropertyPredicate

Property Type Description
filterableProperty FilterablePropertyDefinition The property the condition filters on.
operator ComparisonOperator The comparison operator.
value any The value to compare with. undefined for ComparisonOperator.IsEmpty.

Filterable property definitions

All definitions take the display name and the property key first. Where available, the optional operators argument replaces the default operators.

Class Optional arguments Description
StringPropertyDefinition operators, singleCondition, logicalOperator Text values. Any number of conditions joined by AND or OR, unless limited.
NumericPropertyDefinition operators, unit, singleCondition, logicalOperator Numbers, optionally with a unit the user can change.
EnumPropertyDefinition values (required), singleSelect, searchable, enableSelectAll A fixed set of options, given as a key-to-label map.
DateTimePropertyDefinition operators, includeSeconds Dates and times: Equals, Before, After, Custom range, Last day/week/month/year, Time span and Is empty.
UserPropertyDefinition Users picked by domain. Requires a provided DatagridFiltersUserService.
